# 外部 MCP 服务：主动注册与在线接入

首版协议标识 `external-mcp/v1`。部署步骤见[Python / Node.js SDK 快速接入](external-mcp/quickstart.md)。

## 1. 目标与边界

外部服务独立部署，使用平台管理员签发的注册凭证主动注册。注册和工具清单校验通过、且外部进程已准备好接单后，平台自动把服务标记为在线。用户继续使用平台现有的 MCP Key 和 `/mcp`，或使用 `/v1/capabilities` 及其调用接口，不需要知道外部服务地址，也不需要更换客户端配置。

主动注册是新增的可选接入方式。平台内置 MCP 能力、已接入的 MCP 服务及其现有配置、鉴权和调用路径不迁移、不改动；已独立部署的 MCP 服务也不必修改源码、配置或重启。需要主动注册时，可另行部署桥接器，不替换原有服务。

**推荐通信方式：外部服务主动拉取任务。** 外部服务通过 HTTPS 调用平台的 REST API 来注册、续租、长轮询领取调用、回传结果。平台不按注册请求中的 URL 回连，外部服务不需要开放入站端口，也不会让平台代为访问任意 URL。已经运行的标准 MCP Server 可通过同机桥接器接入；桥接器使用部署者在本地明确配置的 MCP 端点，不由平台或调用者指定。首版不做远程 MCP 会话、资源、提示词或双向流的透明代理；对外兼容现有平台的 **工具发现和工具调用**。

## 2. 身份、租约与清单

| 对象 | 约束 |
| --- | --- |
| `external_services` | 持久身份，由平台分配不可复用的 `service_id`。保存显示信息、所属人、清单版本及安全配额。相同名称不是同一身份。 |
| `external_service_credentials` | 每个服务独立的高熵注册凭证，只显示一次、服务端仅存摘要；可设有效期、旋转和撤销。它是部署凭证，不是消费侧 MCP Key。SDK 无人值守恢复依赖该凭证仍有效。 |
| `external_instances` | 每次独立进程启动使用持久到该进程结束的 `instance_id`；服务端给出 `lease_epoch`，记录 `last_seen_at`、`lease_expires_at` 和清单版本。注册重试必须幂等，不能凭响应丢失制造第二个实例。移除只清理当前注册实例；新旧租约以代次区分，不设黑名单。 |
| `external_invocations` | 保存 `call_id`、服务/清单版本、状态、截止时间、领取实例和派发版本。参数与结果设大小限制，按短保留期清理；操作日志不复制正文或密钥。 |

注册成功返回实例租约令牌：仅可为该实例心跳、领取和回传，默认 **1 小时**。令牌过期前由 SDK 随心跳续签；每次请求仍查有效租约和实例代次，因此令牌未过期并不意味着实例可以继续工作。消费侧 `mcp-…` Key 只用于平台已有消费接口，按能力白名单授权。不得把消费 Key、注册凭证或平台管理员 JWT 转发到外部工具。

### 注册凭证管理页

在 **MCP 广场 → 外部服务 → 注册凭证** 增加独立管理页，支持按服务、状态筛选。列表只显示名称、所属服务、凭证 ID/可识别前缀、创建者、签发时间、到期时间、最近使用时间和状态（有效、已过期、已销毁），不提供明文找回。查看页与写操作分别授权；凭证只允许操作其所属服务，不能用于访问消费接口。

| 操作 | 行为 |
| --- | --- |
| 签发 | 指定服务、凭证名称及有效期；默认永不过期，可选 7/30/90 天。创建后只显示一次，提供复制和环境变量配置提示，不写入日志。每个服务可有多个凭证，方便独立部署和无停机轮换。 |
| 续期 | 在到期前延长现有凭证的到期时间，或设为永不过期，明文不变、无需重新部署。已过期的凭证不原地恢复，改签新凭证。续期不改变实例租约有效期。 |
| 轮换 | 为同一服务签发一份新凭证，旧凭证继续有效到原到期时间或手动销毁。先更新外部部署并验证新凭证已使用，再销毁旧凭证；页面提示旧凭证仍有效。 |
| 销毁 | 二次确认，提示影响范围；永久吊销该凭证并使由它签发的实例租约立即失效，不能再注册、续租或领单，其他凭证及其租约不受影响。保留脱敏审计记录，不物理删除。 |

实例保存来源 `credential_id`。注册、续租、领单与回传统一校验来源凭证；注册凭证到期则对应实例不可继续对外服务，避免实例持续续签绕过到期。审计记录签发、续期（旧/新到期时间）、轮换和销毁的操作人、时间、凭证 ID 与服务 ID，不记录原始令牌。页面可提示即将到期和受影响实例数。「移除当前注册」仍只清理租约，不销毁凭证，也不改变已部署 MCP 服务。

清单包含 `protocol_version`、服务版本及 `tools[]`；每个工具声明 `name`、`description`、`input_schema`（JSON Schema，对象）、可选 `output_schema`、超时和副作用标记。平台生成稳定能力 ID 和带命名空间的工具名，例如 `ext_acme_docs_search`，拒绝与内置能力或其他服务冲突。验证清单大小、工具数量、名称、字段与 schema；不解析外部 `$ref`，不加载远程代码。标题和返回内容按不可信数据处理。

管理员给服务发凭证即批准其首次有效清单自动上架；**上架不等于给现有 MCP Key 自动授权**。续租、重启时清单未变，可复用该身份下原有授权；新增工具、操作副作用变化或有破坏性的 schema 变更走显式清单发布审核，不能用心跳静默替换有授权的工具。首版可为每个服务限制一个活跃清单版本；未批准的新版本不能领取旧版任务。

## 3. 在线、离线与移除

| 状态 | 管理端 | 对外发现及调用 |
| --- | --- | --- |
| 在线 | 显示实例、版本、最近心跳与在线数量 | 向有权限的 Key 列出工具；允许接单 |
| 离线 | 置灰，保留配置、授权与历史 | 不再列出；持有旧工具名的已授权客户端调用时，REST 返回 `503 service_offline`，MCP 通过现有错误适配层返回等价工具错误 |
| 已移除 | 清理当前注册实例，从在线目录移除；审计保留 | 不再对外提供当前注册的工具；下一次有效注册可自动上线，同一进程也可重新注册 |

- 默认每 **15 秒**心跳，**45 秒**未续租视为离线。使用平台 UTC 时间；判断条件为 `lease_expires_at > now`，发现、分发和领单时即时校验，不等待清理任务。周期任务只负责清理、统计和发通知，不能作为权限判断的唯一来源。
- 首次注册应在 worker 可接单之后发起；注册和首次在线在同一事务提交。心跳与领单分开，长轮询不会阻塞续租。失联恢复时，已过期实例不能仅靠旧心跳复活，SDK 重新注册并获得新代次。
- 管理员点击「移除」时，仅在平台侧清理该服务当前的实例注册及租约，不停外部进程、不撤销注册凭证、不改变服务身份和已批准清单的授权。旧租约不能续租、领单或回传，只是为了避免把旧请求串到新注册。SDK 下次心跳收到 `410 registration_missing` 后走标准注册流程，可用同一个 `instance_id` 获取新代次。若进程一直运行，下一个心跳周期就可能重新出现，这是预期行为；界面应提示「仍在运行的服务可自动重新注册」。撤销凭证是独立的安全操作，不属于移除。
- 瞬时网络抖动使用指数退避加抖动；请求尚未被领取时可取消或超时。对已经领取的调用，不宣称能够远程强杀；离线或移除时不再接受旧代次结果，也不把同一次有副作用操作自动重派。SDK 应协作处理取消和截止时间。

## 4. REST 协议

所有请求走 HTTPS；控制面使用 JSON，文件上传使用二进制请求体。控制面路由与用户消费 API 分开。注册与实例凭证均放 `Authorization: Bearer …`，从日志脱敏。服务端签发的调用参数不接受调用者指定服务地址、转发头或任意代理目标。

| 路由 | 鉴权 | 行为 |
| --- | --- | --- |
| `POST /v1/external-mcp/instances` | 服务注册凭证 | 提交 `instance_id`、协议版本、清单；校验后返回 `service_id`、`lease_epoch`、`lease_token`、心跳间隔、租约截止时间。首次注册 `201`，幂等重试 `200`。 |
| `PUT /v1/external-mcp/instances/{instance_id}/lease` | 实例租约令牌 | 续租，返回平台时间、租约截止时间，临近过期时返回新令牌。 |
| `POST /v1/external-mcp/instances/{instance_id}/claims` | 实例租约令牌 | 最多长轮询 20 秒；原子领取一项有资格的任务；暂无返回 `204`。响应包含 `call_id`、`dispatch_id`、工具名、参数、`deadline_at`、`request_id`。 |
| `PUT /v1/external-mcp/instances/{instance_id}/calls/{call_id}/result` | 实例租约令牌 | 校验领取实例、代次、`dispatch_id` 和截止时间后回传结果。同一结果重传幂等；冲突内容返回 `409`。 |
| `DELETE /v1/external-mcp/instances/{instance_id}/lease` | 实例租约令牌 | SDK 优雅退出时主动下线。进程异常退出依旧由租约超时兜底。 |
| `/api/admin/mcp/external-services` | 管理员权限 | 查看服务和在线状态，发行/轮换/撤销注册凭证、审核清单、移除当前注册。读与管理操作分权限。 |
| `GET /api/admin/mcp/external-services/{service_id}/credentials` | 凭证查看权限 | 列出该服务凭证的脱敏元数据。 |
| `POST /api/admin/mcp/external-services/{service_id}/credentials` | 凭证管理权限 | 签发凭证；明文仅随成功响应返回一次，响应禁用缓存。轮换复用此接口，可关联旧凭证 ID。 |
| `POST /api/admin/mcp/external-services/{service_id}/credentials/{credential_id}/renew` | 凭证管理权限 | 为仍有效的凭证设置更晚的到期时间；只返回元数据。 |
| `DELETE /api/admin/mcp/external-services/{service_id}/credentials/{credential_id}` | 凭证管理权限 | 幂等销毁；立即阻止该凭证关联的实例继续接单，保留审计。 |

工具结果契约：成功返回 `{"dispatch_id":"…","ok":true,"result":{…}}`；失败返回 `{"dispatch_id":"…","ok":false,"error":{"type":"invalid_request","message":"…"}}`。平台校验响应并适配现有 Capability/MCP 错误格式；公共接口不暴露外部堆栈、原始凭证或部署地址。内部 `401` 表示凭证无效，`403` 表示无权限，`410` 区分租约已过期、注册记录不存在（`registration_missing`）和调用已结束，`429` 表示限流或队列上限。消费侧超时返回 `504`，外部执行异常归一为合适的 `4xx`、`502` 或 `504`。

单次同步调用默认 **20 秒**，可配置至 **60 秒**；长任务仍由工具声明 `submit` / `status` / `result` 等应用级操作。平台设置每服务并发与积压上限、过期清理及请求体上限；外部执行开始后不自动重试，开发者可按 `call_id` 做幂等保护。外部服务仅收到所需参数和追踪 ID；需要区分调用方时，平台提供不可跨服务关联的匿名调用方标识，而不是下游密钥。

### 可选：交付文件（PPTX、PDF 等）

1. 领取调用后，worker 用实例租约令牌 `POST /v1/external-mcp/instances/{instance_id}/calls/{call_id}/artifacts`，提交 `{"dispatch_id":"…","filename":"slides.pptx","content_type":"application/vnd.openxmlformats-officedocument.presentationml.presentation","size_bytes":12345}`。网关校验实例、派发 ID 和调用截止时间，返回 `artifact_id`、`upload_url`、`upload_token` 和 `expires_at`。
2. worker 向 `upload_url` 发 `PUT`，使用 `Authorization: Bearer <upload_token>`，请求体是完整文件原始字节，不是 JSON、Base64 或 multipart。必须与申报大小一致，成功返回 `204`。上传 URL 和凭证仅允许写这一个文件，并在本次调用截止时失效；成功后不可覆盖。
3. worker 在截止前回传 `{"dispatch_id":"…","ok":true,"result":{…},"artifact_ids":["…"]}`。网关独立校验 `result` 的输出 schema，只发布本次派发已上传的文件。没用 `artifact_ids` 的旧 worker 和现有分块接口不变。

带文件的 REST 调用返回 `{"result":{…},"artifacts":[{"artifact_id":"…","filename":"slides.pptx","content_type":"…","size_bytes":12345,"download_url":"https://…","expires_at":"…"}]}`；MCP 的 `structuredContent` 使用同一结构，`content` 保留原 JSON 文本，并额外返回标准 `resource_link` 和纯文本下载 URL。是否显示为原生附件取决于 MCP 客户端。下载链接自发布起有效 **15 分钟**，持有者可直接访问，无需 MCP Key；不要公开转发或记录完整链接。网关以附件形式返回文件，不在同源页面内联展示。

- 部署时将 `APP_BASE_URL` 设为 worker 和下载方均可访问的公网 HTTPS 网关根地址。仅本地开发支持回环 HTTP。反代需要允许相应的 `PUT` 请求体大小，并避免在访问日志记录下载路径的查询参数。worker 不需要入站端口，网关也不访问 worker 提供的 URL。
- 首版流式写入数据库同级的 `external_mcp_artifacts/` 目录，网关的进程须共享同一数据卷及数据库。单文件最多 **32 MiB**，单调用最多 **4 个**，共享临时存储配额 **512 MiB**。未发布文件在调用截止后定期清理，已发布文件在链接过期后定期清理。生成较久的 PPT 可在异步任务完成后，由现有 `result` 工具上传本地成品并交付链接。

## 5. 平台接入点

1. **目录与数据层**：现有 `backend/app/capabilities/registry.py` 是进程内的静态注册表；保留内置部分，新增基于数据库的外部目录查询。展示用状态与实际可用性分开，避免把离线误当成删除。管理员目录、消费目录和 MCP Key 授权校验都使用同一套外部身份与清单。
2. **统一执行**：在 `backend/app/capabilities/runtime.py` 接入外部 `Provider` 适配器，复用权限、调用记录、错误归一化。查权限、投递和写结果用短事务，不在等待外部响应期间持有 SQLite 写锁或数据库连接。SQLite 首版用原子领取和有界长轮询；跨 worker 的租约和任务真相以数据层为准，不只存进程内。多节点部署或高并发时再引入共享消息队列，保持接口不变。
3. **MCP 动态工具**：`backend/app/mcp_server.py` 目前只在启动时用 FastMCP 注册工具。保留内置处理器；在请求期合并动态外部 `tools/list`，让 `tools/call` 按名称解析后走同一执行入口，不能只给列表加工具却没有动态调用。外部工具 schema 直接使用已验证的声明；如果协议及客户端支持，按权限发送 `notifications/tools/list_changed`；不支持时，在下一次 `tools/list` 可见，执行端始终拦截已下线工具。
4. **界面**：MCP 广场加「外部服务」来源标签和在线/离线徽标；管理页显示实例、版本、心跳时间、最近失败及操作。只对通过新协议接入的外部服务提供移除入口。接入中心继续按 MCP Key 生成 REST 和 MCP 配置，不暴露注册凭证或 worker 端地址。内置 AI 助手首版不自动获得外部工具，后续可通过独立授权接入。

### 对外能力与内置 MCP 一致

SDK 注册成功后，外部服务成为**平台上的正式能力**，而不是只在管理页显示「已在线」。通过现有 MCP Key 授权后，同一把 Key 可同时调用内置和外部能力：

| 对外入口 | 外部能力的行为 |
| --- | --- |
| MCP `/mcp` | 出现在同一个 `tools/list`，以平台分配的工具名通过 `tools/call` 调用，沿用平台现有鉴权、结果格式、错误处理与调用记录。 |
| REST `/v1/capabilities` | 出现在同一份能力目录，通过 `POST /v1/capabilities/{capability_id}/{operation}` 调用。工具名与 REST 操作名映射由平台生成并固定在同一清单版本。 |
| MCP 广场、Key 授权、接入说明 | 与内置能力共用现有入口。`GET /api/admin/mcp/keys/{key_id}/integration` 从同一份外部能力目录读取清单和授权状态。接入说明沿用平台地址、MCP 客户端配置、REST/cURL 示例以及可复制的 MCP 和「Skill + REST」提示词。 |

SDK 清单允许声明工具用途、输入/输出 schema、可选示例参数、结果说明和使用备注。平台据此生成 `integration.rest_endpoints`、工具参数表和调用示例；开发者不用另写页面。示例发送到**平台**地址，平台生成路径及方法，不采用外部服务提交的 URL、请求头、密钥或脚本。没有示例参数时，显示 schema 和必填字段，不编造可运行的业务参数。清单文案按纯文本渲染，消费侧配置只使用自己的 MCP Key（文档示例默认用占位符），不包含注册凭证或租约令牌。

管理端接入说明可显示授权过但离线的能力，并标注「当前不可调用」、保留授权；在线可调用的配置、示例和 AI 提示词只包含**当前在线且该 Key 已授权**的工具。重新上线且清单不变时，原有 Key 无需重新授权，接入说明自动恢复展示。旧客户端或已复制的示例仍以调用时的在线判定为准。

## 6. SDK 与教程的交付范围

- 提供 **Python SDK 和 Node.js SDK**、版本化 OpenAPI、JSON Schema 和两份可运行示例。SDK 封装清单生成、注册、实例身份、续租、长轮询、截止时间、异常归一化、协作取消和优雅退出。收到注册记录不存在的响应时，暂停使用旧租约，自动重注册后恢复接单。Python 目录另提供从本机标准 MCP `tools/list`/`tools/call` 转接的桥接器示例，固定本地配置，禁止把用户参数解释成连接地址。
- 教程路径建议 `docs/external-mcp/quickstart.md`：平台创建服务与注册凭证 → 实现示例 `echo` 工具 → 通过环境变量配置平台地址和凭证 → 部署 worker → 在 MCP Key 中授权 → 分别用 REST 和 MCP 验证 → 停止 45 秒观察置灰 → 手动移除与重新上线 → 轮换凭证及排错。不要在示例、日志或镜像中放真实凭证。
- 首版验收：无效凭证、过期/旧代次、清单冲突、越权 Key 都被拒绝；注册后无需重启即可发现与调用；断心跳后 REST/MCP 都不可调用；移除后旧租约无效，但同一进程凭有效注册凭证可自动重新注册；重复领取无双派、结果重传幂等；其他 MCP Key 不会因为外部服务上线而自动获得权限；已有 MCP 接入行为不变。用模拟时钟测试 45 秒窗口，用公开 `echo` fixture 做 SDK、REST、MCP 端到端测试。
- 接入说明验收：仅部署 SDK 示例、完成注册并为一个现有 Key 授权，不手写能力文档、不重启平台；接入中心能列出外部工具并生成可用的 MCP 配置和 REST 示例。用该 Key 分别完成 `tools/list`、`tools/call` 和 REST 调用；另一个未授权 Key 不可发现或调用该能力，生成的接入材料也不包含它。模拟离线、重注册和清单版本变化，验证说明与实际可用接口一致。

## 7. 实施顺序

1. 控制面与租约：数据库、服务凭证、注册、心跳、移除当前注册、审计与状态测试。
2. 执行面：领取和回传、统一权限、REST/MCP 动态发现与分发、离线和超时测试。
3. 管理页面、Python SDK、OpenAPI 和接入教程；用一个外部示例部署验证完整链路，再评估 TypeScript SDK 和更高并发方案。
