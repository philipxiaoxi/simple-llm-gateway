## 一、阿里云 DashScope 实时语音识别（Paraformer）

### 1.1 实测结论（2026-09-10 在本机验证）

用用户提供的 Key 直接连真实服务，两个模型都跑通了完整生命周期：

```
=== paraformer-realtime-v2 ===
  connected  : HTTP 101，server: istio-envoy
  event      : task-started   {"header":{"task_id":"…","event":"task-started","attributes":{}},"payload":{}}
  (发送 800ms 静音 PCM16 16kHz 二进制帧)
  event      : task-finished  {"header":{...,"attributes":{"request_uuid":"…","x-ds-batch-queue-length":"0"}},"payload":{"output":{}}}

=== fun-asr-realtime ===
  connected  : HTTP 101
  event      : task-started
  event      : result-generated  × N   (sentence.text 为空，因为喂的是静音)
  event      : task-finished
```

**结论**：
1. `sk-ws-…` 这个 Key 直接可用，**不需要** AppKey/Token 那套（那是老的智能语音交互 NLS 产品，与本 Key 无关）。
2. 端点：`wss://dashscope.aliyuncs.com/api-ws/v1/inference`
3. 鉴权：握手头 `Authorization: Bearer <API_KEY>`（`websockets` 客户端用 `additional_headers=`）
4. 音频用**二进制帧**直接发原始 PCM，**不需要 base64**
5. 无需发送 `X-DashScope-DataInspection`（官方明确说非必要不启用）
6. **同一个 Key 可以调用同端点的多个模型**，已实测 `qwen-audio-3.0-asr-flash-streaming`、`fun-asr-realtime`、`paraformer-realtime-v2` 三者共用同一份 `run-task` 报文，只有 `payload.model` 不同

### 1.1.1 模型选型（结论）

| 模型 | 协议 | 单价（元/秒） | 字级时间戳 | 结论 |
|---|---|---|---|---|
| `qwen-audio-3.0-asr-flash-streaming` | `run-task` | 0.00033 | ✅ | **默认采用**（同价中效果最好） |
| `fun-asr-realtime` | `run-task` | 0.00033 | ✅ | 备选（中英混说 / 噪声环境） |
| `paraformer-realtime-v2` | `run-task` | 0.00024 | ✅ | 备选（省钱，中间结果更密） |
| `qwen3-asr-flash-realtime` | `session.*` ❌ | 0.00033 | ❌ | **不用**：会话式协议、无时间戳、不支持连接复用 |

真实中文语音实测对比见 [技术方案.md §4.4.1](./技术方案.md#441-实时-asr-模型选型实测对比)。

### 1.2 完整交互时序

```
客户端                                服务端
  │  ── WSS 握手（Authorization: Bearer sk-ws-…）──►
  │  ◄────────────── 101 Switching Protocols ──────
  │
  │  ── {"header":{"action":"run-task",…}} ────────►
  │  ◄──────────── {"header":{"event":"task-started"}}      ← 收到后才能发音频
  │
  │  ── 二进制帧：PCM16LE 16kHz 单声道 ─────────────►
  │  ◄──────────── {"header":{"event":"result-generated"}}  ← 可多次（中间结果）
  │  ◄──────────── {"header":{"event":"result-generated"}}  ← sentence_end=true 为终稿
  │  …（持续双向）
  │
  │  ── {"header":{"action":"finish-task",…}} ─────►
  │  ◄──────────── {"header":{"event":"task-finished"}}     ← 之后可关闭连接
  │
  │  ── 关闭 ──────────────────────────────────────►
```

失败路径：`{"header":{"event":"task-failed","error_code":"…","error_message":"…"}}`，**连接会被服务端关闭且不可复用**。

### 1.3 `run-task` 报文（本项目取值）

```json
{
  "header": {
    "action": "run-task",
    "task_id": "e58f4007-57a5-4e55-95c8-88f24cd3f42e",
    "streaming": "duplex"
  },
  "payload": {
    "task_group": "audio",
    "task": "asr",
    "function": "recognition",
    "model": "qwen-audio-3.0-asr-flash-streaming",
    "parameters": {
      "format": "pcm",
      "sample_rate": 16000,
      "disfluency_removal_enabled": true,
      "punctuation_prediction_enabled": true,
      "inverse_text_normalization_enabled": true,
      "semantic_punctuation_enabled": false,
      "max_sentence_silence": 700,
      "heartbeat": true,
      "language_hints": ["zh"]
    },
    "input": {}
  }
}
```

字段说明（仅列与本项目相关的）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `header.action` | `run-task` | 固定 |
| `header.task_id` | UUID | 客户端生成；`finish-task` 必须用同一个 |
| `header.streaming` | `duplex` | 固定 |
| `payload.task_group` | `audio` | 固定 |
| `payload.task` | `asr` | 固定 |
| `payload.function` | `recognition` | 固定 |
| `payload.model` | `qwen-audio-3.0-asr-flash-streaming` | 房间可覆盖；同协议备选 `fun-asr-realtime` / `paraformer-realtime-v2` |
| `format` | `pcm` / `wav` / `opus` / `speex` / `aac` / `amr` / `mp3` | 我们用 `pcm` |
| `sample_rate` | `paraformer-realtime-v2` 支持任意；`v1` 仅 16000；`8k-v2` 仅 8000 | 我们用 16000 |
| `disfluency_removal_enabled` | **`true`** | 开：直接删掉「嗯/那个/就是说」等语气词并重组标点。实测关掉时 ASR 一个赘词都不删，只加标点——所以这档必须开（房间可关）。模型支持度：Qwen / Paraformer 效果明显，Fun-ASR 较弱 |
| `punctuation_prediction_enabled` | `true` | 开：原文也带标点，便于润色 |
| `inverse_text_normalization_enabled` | `true` | 开：中文数字转阿拉伯数字 |
| `semantic_punctuation_enabled` | `false` | 关：用 VAD 断句（延迟低，适合交互） |
| `max_sentence_silence` | `700` | 默认 1300；调小让句子更快定稿，润色更早介入。范围 [200,6000] |
| `heartbeat` | `true` | 开：长时间静音也不断连（仅 v2 支持） |
| `language_hints` | `["zh"]` | 也可加 `en`；不传则自动识别 |

### 1.4 `finish-task` 报文

```json
{
  "header": { "action": "finish-task", "task_id": "<与 run-task 相同>", "streaming": "duplex" },
  "payload": { "input": {} }
}
```

### 1.5 服务端事件

| event | 关键字段 | 处理 |
|---|---|---|
| `task-started` | `header.task_id` | 打开音频闸门 |
| `result-generated` | `payload.output.sentence.{text,sentence_end,begin_time,end_time}`；`payload.usage.duration` | `sentence_end=false` → 中间结果；`true` → 该句终稿（`usage.duration` 此时才有值，单位秒）；`sentence.heartbeat=true` → 心跳包，跳过 |
| `task-finished` | `payload.output` | 会话正常结束 |
| `task-failed` | `header.error_code` / `header.error_message` | 会话失败，连接不可复用 |

`fun-asr-realtime` 会额外返回 `sentence_id`、`sentence_begin`、`stash`；`paraformer-realtime-v2` 的 `words[]` 提供字级时间戳（本期不用）。

### 1.6 约束与配额

| 项 | 值 |
|---|---|
| 音频格式 | Paraformer：`opus/speex` 必须 Ogg 封装；`wav` 必须 PCM 编码；`amr` 仅 AMR-NB |
| 声道 | 必须单声道 |
| 空闲超时 | 任务结束后 60s 无新任务，连接自动断开 |
| 连接复用 | `finish-task` 后收到 `task-finished` 才能发下一个 `run-task`；任务失败不可复用 |
| 限流 | 按账号有并发/QPS 限制，需在网关侧加全局信号量（见方案 §8） |
| 计费 | 按 `usage.duration`（秒）计；服务端会返回 `x-ds-batch-queue-length` 反映排队 |

### 1.7 推荐音频参数（浏览器端采集）

| 参数 | 值 | 理由 |
|---|---|---|
| 采样率 | 16000 Hz | Paraformer 最佳；浏览器原生 48k → 3:1 线性插值 |
| 位深 | 16-bit signed LE | DashScope PCM 约定 |
| 声道 | 1 | 必须 |
| 帧长 | 100ms（3200 字节） | 延迟与包开销平衡；官方无硬性下限，但过小会增加 WS 帧数开销 |
| 编码 | 无（裸 PCM） | 不做 Opus：可省去服务端 `ffmpeg` 依赖 |

### 1.8 Python 客户端要点（`websockets` 17）

```python
from websockets.asyncio.client import connect

async with connect(
    "wss://dashscope.aliyuncs.com/api-ws/v1/inference",
    additional_headers={"Authorization": f"Bearer {api_key}"},
    max_size=2 ** 22,
    ping_interval=20,
    ping_timeout=20,
    close_timeout=5,
    open_timeout=10,
) as ws:
    await ws.send(json.dumps(run_task_payload))
    ...
    await ws.send(pcm_bytes)          # 二进制帧
```

> 注意：`websockets` 旧版参数名是 `extra_headers`，17.x 用 `additional_headers`。本项目 venv 为 17.0.1。

## 二、本项目自定义 WS 协议（完整定义）

### 2.0 通用约定

- 控制帧：JSON 文本帧，均含 `type`
- 音频帧：二进制帧（仅手机 → 服务端）
- 服务端下发的所有消息带 `ts`（epoch ms）
- 心跳：双向 `{"type":"ping"}` → `{"type":"pong"}`，**客户端每 15s 主动发一次**（服务端不主动 ping，与现有 `/agent/connect` 约定一致）
- 重连：客户端指数退避（1s → 2s → 4s → 8s → 上限 30s），带 ±20% 抖动
- 幂等：桌面端按 `(segId, rev)` 去重；服务端可安全重发

### 2.1 端点总览

| 端点 | 作用 | 鉴权 |
|---|---|---|
| `WSS /api/voice/rooms/{room_id}/phone?token=<JWT>` | 手机上行音频 + 接收字幕 | 房间作用域 JWT（`role=phone`） |
| `WSS /api/voice/desktop/connect` | 桌面端注册 + 接收文本段 + 回执 | 首帧 `register` 里的令牌（`role=desktop`） |

### 2.2 令牌

```
payload = {
  "scope":   "voice",
  "role":    "phone" | "desktop",
  "room_id": "a1b2c3d4",
  "cid":     "<client_uid>",
  "iat":     1757500000,
  "exp":     1757543200          # phone: 12h；desktop: 30d
}
签名：HS256，密钥 = APP_SECRET_KEY
```

校验规则（服务端）：
1. `jwt.decode(token, app_secret_key, algorithms=["HS256"])`，`PyJWTError` → 关闭码 `1008`
2. `payload["scope"] != "voice"` → `1008`
3. `payload["role"]` 与端点要求的角色不符 → `1008`
4. URL 里的 `room_id` 与 `payload["room_id"]` 不符 → `1008`（**防跨房间越权**）
5. `exp` 过期 → `1008`

> 桌面端首帧注册可以用两种凭据二选一：房间 JWT（推荐，可精确到设备）或全局 `VOICE_DESKTOP_TOKEN`（对标 `LOCAL_AGENT_TOKEN`，便于人工配置）。

### 2.3 手机端协议

#### 客户端 → 服务端

| type | 字段 | 说明 |
|---|---|---|
| `hello` | `clientUid`, `name`, `sampleRate`, `format` | 连接后第一条；服务端据此登记设备与音频参数 |
| `start` | `recordingId` | 开始录音；服务端建会话并连 DashScope |
| *(binary)* | PCM16LE 单声道 16kHz | 100ms/帧 |
| `stop` | — | 松开按钮 |
| `discard` | — | 上滑取消（丢弃本段） |
| `ping` | — | 心跳 |

#### 服务端 → 客户端

| type | 字段 | 说明 |
|---|---|---|
| `ready` | `room`, `sessionUid`, `roomState`, `asrModel` | `hello` 的应答 |
| `asr.partial` | `segId`, `seq`, `text` | 中间结果（边说边出字） |
| `asr.final` | `segId`, `seq`, `text` | 句子终稿（ASR 原文） |
| `segment.revised` | `segId`, `seq`, `text`, `polishMs`, `model` | AI 优化后的文本 |
| `segment.ack` | `segId`, `rev`, `ok`, `chars` | 电脑端已填入的回执（手机上显示 ✓） |
| `segment.abort` | `segId`, `reason` | 该段被撤销 |
| `room.state` | `busy`, `phones`, `desktops` | 房间在线状态变化 |
| `session.done` | `sessionUid`, `sentences`, `audioMs` | 会话收尾完成 |
| `warning` | `code`, `message` | 非致命（如「电脑端离线」） |
| `error` | `code`, `message` | 致命（如 ASR 失败），随后服务端可能关闭连接 |
| `pong` | — | 心跳应答 |

#### 错误码

| code | 含义 | 客户端表现 |
|---|---|---|
| `ASR_UNAVAILABLE` | 阿里云不可达/未配置 | 红条，禁止录音 |
| `ASR_FAILED` | 会话中失败 | 保留已识别文字，提示 |
| `ROOM_FULL` | 超并发 | 提示 |
| `TOKEN_INVALID` | 令牌失效 | 跳回 join 页 |
| `BACKPRESSURE` | 音频积压丢帧 | 弱提示 |

### 2.4 桌面端协议

#### 客户端 → 服务端

| type | 字段 | 说明 |
|---|---|---|
| `register` | `roomId`, `token`, `clientUid`, `name`, `caps`, `insertMode` | 首帧 |
| `segment.ack` | `segId`, `rev`, `ok`, `action`, `chars`, `text` | `action`: `inserted` / `replaced` / `appended` |
| `segment.abandoned` | `segId`, `reason` | 放弃替换。真·放弃：`cursor_mismatch` / `user_typed` / `mode_off` / `disabled`；延后超时降级：`timeout` / `room_busy` |
| `inject.error` | `segId`, `reason` | `no_focus` / `perm_denied` / `clipboard_failed` / `secure_input` |
| `status` | `insertMode`, `foregroundApp`, `canInject` | 状态上报（每 30s 或变化时） |
| `ping` | — | 心跳 |

#### 服务端 → 客户端

| type | 字段 | 说明 |
|---|---|---|
| `registered` | `room`, `roomState`, `recentSegments` | 注册成功；`recentSegments` 补发最近 5 段**已定稿**段落，每项含 `segId/seq/rev/state/text/final/rawText/polishedText`，其中 `text` 是当前应显示的版本（纠错稿优先），`final` 表示服务端承诺不再改动 |
| `segment.snapshot` | `segId`, `seq`, `rev`, `text`, `final`, `roomBusy` | **唯一的下发文本消息**，始终是整段快照 |
| `segment.abort` | `segId`, `reason` | 要求撤掉该段 |
| `room.state` | `busy`, `phones`, `desktops` | 状态变化 |
| `pong` | — | 心跳应答 |

#### `rev` 语义（客户端行为依据）

> **重要：`rev` 是「状态档位」不是「自增版本号」。** 同一段在 `rev=0` 阶段会被反复下发
> （服务端按 ≥120ms 节流，`text` 持续增长），`rev=1` 是 ASR 终稿，`rev=2` 是纠错终稿。
> 因此客户端**不能**用 `(segId, rev)` 做去重，也不能简单地「rev 不大于本地就丢弃」——
> 否则一句话只会显示第一帧中间结果。正确做法：去重键用 `(segId, rev, text)`；
> 只在 `rev < 本地 rev` 时丢弃；同 rev 用「共同前缀 diff」判断是否真的需要重贴。

| rev | state | final | 可重复？ | 客户端行为 |
|---|---|---|---|---|
| 0 | partial | false | **是，多次** | 可自由替换（文本持续增长） |
| 1 | final | false | 否 | 可替换（等纠错） |
| 2 | revised | true | 否 | **committed**：只允许正向追加，不再回改 |

#### 闸门语义：`roomBusy` / `tooSoon` 是「延后」不是「放弃」

`roomBusy=true` 表示房间里还有人正在录音。此时**不应放弃替换**，而应把这次替换**推迟**到
房间空闲后再执行——否则纠错终稿（rev=2）永远替换不回去，核心功能就废了。同理，距上次注入
过近（`tooSoon`）也应短暂延后。推荐上限：`tooSoon` ≤ 3s，`roomBusy` 到录音停止（上限同
`maxRecordingSeconds`）；超时才降级为「只追加」并上报 `segment.abandoned`。
`disabled` / `mode_off` / `cursor_mismatch` 这三类才是立即放弃。

### 2.6 关闭码约定

| code | 含义 |
|---|---|
| `1000` | 正常关闭 |
| `1008` | 鉴权失败 / 令牌与房间不符 / 角色不符 |
| `1011` | 服务端内部错误 |
| `1006` | 网络异常断开（客户端应重连） |
