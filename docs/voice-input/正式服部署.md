# 正式服部署指南：手机语音输入

> 面向 `https://xapi.xiaotao2333.top:344`（nginx 1.31.1 → Docker `gateway:8000`）。
> 部署方式与仓库既有流程一致：`docker compose up --build`。
> 相关设计见 [技术方案.md](./技术方案.md)。

---

## 0. 结论速览

| 要做的事 | 必须？ | 说明 |
|---|---|---|
| 服务器 `.env` 补 2 个变量 | ✅ **必须** | 阿里云 Key 与桌面端令牌不在仓库里 |
| `docker compose up --build` | ✅ **必须** | 镜像里构建前端 `dist`，不重建就没有新页面 |
| nginx 配置改动 | ❌ **不需要** | 已实测放行 WebSocket 升级（见 §4.1） |
| 数据库迁移 | ❌ **不需要** | 5 张新表由 `create_all` 自动建，`./data` 卷不动 |
| HTTPS 证书 | ❌ **不用动** | 已有，手机麦克风依赖它 |

预计停机窗口：**重新构建期间**（前端 `npm run build` + pip 安装）。网关 API 会短暂不可用。

## 1. 部署前准备（在服务器上）

### 1.1 拉代码

```bash
cd /path/to/llm-gateway
git fetch origin
git checkout 260910-perf-api-assets-speedup     # 或 PR 合并后的 main
git pull
```

确认拿到本次改动：

```bash
ls docs/voice-input/          # 应看到技术方案.md 等
ls voice-desktop/src/         # 应看到 index.js / inject.js
```

### 1.2 补两个环境变量

这两个值**不在 git 里**（`.env` 被忽略），必须在服务器上手动补。

```bash
# 先备份
cp .env .env.bak.$(date +%Y%m%d%H%M)
```

追加到 `.env`：

```bash
# ---- 语音输入 ----
# 阿里云百炼实时语音识别 Key。只存服务端，绝不下发到浏览器
ALIYUN_DASHSCOPE_API_KEY=sk-ws-在这里填你的真实Key

# 电脑端共享令牌（对标 LOCAL_AGENT_TOKEN），用于 voice-desktop 直接连房间
VOICE_DESKTOP_TOKEN=在这里填一段随机长字符串
```

生成随机令牌：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(24))"
```

**可选**（不改也能跑，默认值见 `.env.example`）：

| 变量 | 默认 | 什么时候要改 |
|---|---|---|
| `ALIYUN_ASR_MODEL` | `qwen-audio-3.0-asr-flash-streaming` | 想换识别模型（也可在房间配置里单独改） |
| `VOICE_POLISH_MAX_TOKENS` | `2048` | 纠错换成推理型模型仍报「token 预算耗尽」时调大 |
| `VOICE_POLISH_TIMEOUT_SECONDS` | `12` | 上游模型很慢时调大 |
| `VOICE_EVENT_RETENTION_DAYS` | `30` | 想多留/少留事件日志 |
| `APP_BASE_URL` | 当前值 | **建议改成 `https://xapi.xiaotao2333.top:344`**，这样后台「复制电脑端配置」给出的 `serverUrl` 是 `wss://` 而不是 `ws://127.0.0.1:8000` |

> ⚠️ `.env` 里的 `ALIYUN_DASHSCOPE_API_KEY` 一旦泄露要立刻去阿里云控制台吊销重发。
> 提交前记得确认 `git status` 里没有 `.env`。

### 1.3 确认上游纠错账号可用

纠错走的是**本站已有的上游账号**。上线前在后台确认至少有一个 `active` 账号：

- 打开后台 →「上游账号」，看有没有探测失败的（`last_probe_ok=false`）
- 我本地实测时「智谱开放平台」账号 Key 已失效（`AuthenticationError`），
  如果生产也用它，需要在房间配置里换成可用账号

## 2. 部署

```bash
docker compose up --build -d
docker compose logs -f gateway --tail=80
```

启动日志里应看到 `Application startup complete`，且**没有** `APP_SECRET_KEY 未设置` 之类的告警。

> 若原来没用 `-d`，第一次建议先前台跑一次看日志，确认无误后再 `Ctrl+C` 改守护模式。

**不需要做的事**（避免误操作）：

- ❌ 不要 `docker compose down -v`（会删掉 `./data` 卷，**丢失数据库**）
- ❌ 不要执行任何数据库迁移脚本
- ❌ 不要手动改 nginx

### 3.4 浏览器实测

1. 后台 →「语音房」→ 新建房间（或复用已有的）
2. 房间配置里选好**纠错账号 + 模型**，点「试跑纠错」看有没有输出
   - 有输出 → 纠错链路通
   - 报 `AuthenticationError` → 该账号 Key 失效，换一个
3. 手机浏览器打开 `https://xapi.xiaotao2333.top:344/voice/join?code=<房间码>`
   - 应看到「房间：xxx」→ 点加入
   - 🔴 若提示「需要 HTTPS」→ 你用的不是 https 地址
   - 🔴 若提示「识别服务不可用」→ `ALIYUN_DASHSCOPE_API_KEY` 没配或无效
4. 按住说话，屏幕应**边说边出字**；松手后句子会被 AI 纠错原地替换
5. 后台房间页 →「识别日志」应看到：原文、纠错后文本、状态、耗时、下发/回执

### 3.5 电脑端

```bash
cd voice-desktop && npm install
./scripts/run-voice-desktop.sh     # 或 node src/index.js
```

首次需要授权：系统设置 → 隐私与安全性 → **辅助功能** → 勾选你的终端；
并允许「想要控制 System Events」的弹窗。**授权后要重启终端**。

配置从后台房间页点「复制电脑端配置」拿到，存成 `~/.llm-gateway-voice.json`。
启动后按 `i` 进插入模式，才会真正写入输入框。

## 4. 反代说明（结论：不用改）

### 4.1 已实测放行

线上 nginx 对 `/agent/connect` 返回 `101 Switching Protocols`，说明 `Upgrade` /
`Connection` 头已经正确转发。**`/api/voice/**` 走同一套 `location` 规则，无需新增配置。**

若将来换了反代或有人改动配置，确保包含（现有配置里应该已有）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;      # 语音连接是长连接，别用默认 60s 掐断
}
```

> `proxy_read_timeout` 很关键：默认 60s 会把正在录音的 WebSocket 掐断。
> `/agent/connect` 因为有心跳可能掩盖了这个问题，语音房间的静默期更长。

### 4.2 停机影响

容器重启会导致：**所有正在使用的语音房间连接断开**（前端会自动重连并补发最近 5 段），
网关 API 请求短暂失败。房间配置、段落、日志都在 `./data/gateway.db` 里，不丢。

建议在无人使用时部署。

## 6. 易踩的坑

| 现象 | 原因与处理 |
|---|---|
| `/voice-worklet.js` 返回 `text/html` | 前端 `dist` 是旧的。Dockerfile 会在镜像里构建，所以「没重建镜像」是最常见原因 |
| 手机提示「识别服务不可用」 | `ALIYUN_DASHSCOPE_API_KEY` 缺失/写错/余额不足 |
| 手机提示「需要 HTTPS」 | 非安全上下文。`127.0.0.1` 可以，局域网 IP 不行 |
| 纠错报「token 预算被推理过程耗尽」 | 换了推理型模型，调大 `VOICE_POLISH_MAX_TOKENS` 或换非推理模型 |
| 录音约 60 秒后断开 | 反代 `proxy_read_timeout` 太小（见 §4.1） |
| 「复制电脑端配置」给的是 `ws://127.0.0.1:8000` | `APP_BASE_URL` 还是默认值，改成线上 https 地址 |
| 文字记录了但电脑没上屏 | 电脑端没连上，或没按 `i` 进插入模式；看「事件时间线」的 `放弃替换` / `注入失败` |
| 电脑端报 `-10004 权限违例` | 终端没授予辅助功能/自动化权限，授权后**重启终端** |
| 数据库文件持续变大 | 语音日志增长。清理任务每天自动跑；也可用 `/api/admin/voice/cleanup` 手动清 |

## 7. 上线后建议

1. **观察成本**：阿里云 ASR 按音频秒计费（`0.00033 元/秒` ≈ 每天说 1 小时约 1.19 元）。
   新账号有 36,000 秒免费额度。
2. **观察纠错价值**：房间「识别日志」里看有多少句是 `no_change`。如果长期几乎全是
   `no_change`，说明你的语料本来就干净，可以把该房间的纠错档位改成 `off`，省掉那一跳延迟。
3. **日志清理已自动**：应用启动 2 分钟后跑第一次，之后每 24 小时清理一次超过
   `VOICE_EVENT_RETENTION_DAYS`（默认 30 天）的段落与事件，分批 2000 行删除，
   不会长时间占用 SQLite 写锁。日志里会看到 `[voice] 日志清理完成：…`。
   需要手动清理或看规模时：

   ```bash
   # 当前规模与保留策略
   curl -s -H "Authorization: Bearer <管理员令牌>" \
     https://xapi.xiaotao2333.top:344/api/admin/voice/storage
   # 立即清理（例如只保留 7 天；retention_days=0 为安全阀，什么都不删）
   curl -s -X POST -H "Authorization: Bearer <管理员令牌>" \
     "https://xapi.xiaotao2333.top:344/api/admin/voice/cleanup?retention_days=7"
   ```
