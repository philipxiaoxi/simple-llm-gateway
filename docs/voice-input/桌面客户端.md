# 桌面客户端设计：`voice-desktop`

> 配套文档：[技术方案.md](./技术方案.md) · [协议参考.md](./协议参考.md)
> 职责：常驻本机，通过 WebSocket 连到网关的房间，把服务端下发的文本**填写进当前输入框**，并把「已填入 / 已替换 / 放弃」的回执上报。

---

## 1. 为什么是 Node 进程而不是桌面 App

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Node 命令行 + 系统命令注入 | 无原生依赖、跨平台易改、启动快、和仓库现有 `agent/` 风格一致 | 无托盘 UI | **v1 采用** |
| Electron / Tauri | 有托盘和设置界面 | 包体大、构建链复杂、本期收益低 | P1/P2 |
| 浏览器扩展 | 无需装东西 | 只能注入网页，进不了 VSCode/微信 | ❌ |

关键点：**注入本身不需要原生模块**。macOS 上用 `pbcopy` + `osascript` 就能做到跨 App 的稳定中文输入；引入 `nut-js` / `robotjs` 这类原生模块反而会带来 `node-gyp` 重建和权限问题。

## 3. 注入实现（macOS）

### 3.1 为什么用剪贴板

| 方式 | 中文/emoji | 跨 App | 触发输入法 | 结论 |
|---|---|---|---|---|
| `CGEventKeyboardSetUnicodeString` | ✅ | ✅ | ⚠️ 可能弹出候选框 | 备选 |
| 逐字符 keycode 映射 | ❌ 需键盘布局 | ✅ | ❌ 会打断输入法 | ❌ |
| Accessibility API 直接写控件 | ✅ | ❌ Electron/Qt 不可写 | ✅ | ❌ |
| **`pbcopy` + `Cmd+V`** | ✅ | ✅ | ✅ 不触发候选框 | **主方案** |

`Cmd+V` 走的是应用的粘贴命令，对输入法完全透明，也是讯飞/微信语音输入在 macOS 上的实际做法。

### 3.2 基础操作封装

```js
// src/inject.js  (macOS 实现)
import { execFile } from 'node:child_process'
import { promisify } from 'node:util'
const run = promisify(execFile)

/** 把文本写入系统剪贴板（不经 shell，避免转义问题） */
export async function setClipboard(text) {
  await new Promise((resolve, reject) => {
    const child = execFile('pbcopy', [], (err) => (err ? reject(err) : resolve()))
    child.stdin.end(text, 'utf8')
  })
}

export async function getClipboard() {
  const { stdout } = await run('pbpaste')
  return stdout
}

/** 发送 Cmd+V */
export async function pressPaste() {
  await run('osascript', ['-e',
    'tell application "System Events" to keystroke "v" using command down'])
}

/** 左移选中 n 个字符（Shift+←），分批以降低单次 osascript 开销 */
export async function selectBack(n, batch = 20) {
  let left = n
  while (left > 0) {
    const step = Math.min(left, batch)
    // key code 123 = ←；用 repeat 减少 osascript 调用
    await run('osascript', ['-e',
      `tell application "System Events" to repeat ${step} times\n` +
      `  key code 123 using shift down\n` +
      `end repeat`])
    left -= step
  }
}

/** 退格 n 次 */
export async function pressBackspace(n, batch = 20) { /* 同理，key code 51 */ }
```

### 3.3 一次「注入或替换」的完整动作（原子性）

```js
export async function injectTail({ tailOld, tailNew, restoreClipboard, savedClipboard }) {
  if (tailOld === 0) {
    await setClipboard(tailNew)
    await pressPaste()
    return 'appended'
  }
  await setClipboard(tailNew)
  await selectBack(tailOld)      // 选中旧尾部
  await pressPaste()             // 选中即被覆盖 → 原子替换
  return 'replaced'
}
```

- `tailOld = 0`（纯追加）只需一次粘贴，极快。
- `tailOld > 0` 时**先选中再粘贴**，期间不产生中间态（不会出现「删了一半」的闪烁）。
- `tailNew` 为空（纯回删）则只做 `selectBack` + 一次 `Delete`。

### 3.4 剪贴板保护

注入会覆盖用户剪贴板。策略：

1. 注入前 `getClipboard()` 保存原内容（仅在第一次注入时保存）
2. 注入后 `300ms` 还原
3. `config.clipboardRestore = false` 可关闭

> 权衡：还原窗口内如果用户自己复制了东西会被覆盖。因此还原前再 `getClipboard()` 比对，若已被改动则**放弃还原**。

## 4. 段落账本与替换算法（`src/segments.js`）

纯函数实现，便于单测（`node --test`）。

```js
/** Unicode 字符级公共前缀长度（正确处理 emoji / 代理对） */
export function commonPrefixLen(a, b) {
  const A = Array.from(a), B = Array.from(b)
  const n = Math.min(A.length, B.length)
  let i = 0
  while (i < n && A[i] === B[i]) i++
  return i
}

/** 计算把已注入的 prev 变成 next 所需的最小尾部操作 */
export function diffTail(prev, next) {
  const p = commonPrefixLen(prev, next)
  const prevChars = Array.from(prev).length
  const tailOld = prevChars - p
  const tailNew = Array.from(next).slice(p).join('')
  return { tailOld, tailNew, prefix: Array.from(prev).slice(0, p).join('') }
}
```

账本：

```js
export class SegmentLedger {
  constructor() { this.map = new Map(); this.expectedPos = null }

  /** 返回需要执行的动作，或 null 表示无需操作 */
  plan({ segId, rev, text, final }) {
    const prev = this.map.get(segId)
    if (!prev) return { kind: 'insert', text, segId, rev, final }
    if (rev <= prev.rev) return null                     // 幂等：旧版本直接丢
    const { tailOld, tailNew } = diffTail(prev.text, text)
    if (tailOld === 0 && tailNew === '') return null
    if (prev.committed && tailOld > 0) {                 // 已落定：只允许正向追加
      return tailOld > 0 && tailNew === '' ? null : { kind: 'append', tailNew, /* … */ }
    }
    return { kind: tailOld === 0 ? 'append' : 'replace', tailOld, tailNew, segId, rev, final }
  }

  commit({ segId, rev, text, final }) {
    this.map.set(segId, { text, rev, committed: final })
  }

  /** 用户可能手动输入了 → 放弃所有未落定段落的替换权 */
  abandonAll(reason) {
    const abandoned = []
    for (const [segId, seg] of this.map) {
      if (!seg.committed) { seg.committed = true; abandoned.push({ segId, reason }) }
    }
    return abandoned
  }
}
```

### 4.1 决定「是否允许替换」的三道闸

```js
function canReplace(msg /* segment.snapshot */, cfg, ledger) {
  if (!cfg.replaceEnabled)          return 'disabled'
  if (!insertModeActive())          return 'mode_off'
  if (msg.roomBusy)                 return 'room_busy'      // 还有人在录音，先只追加
  if (Date.now() - lastInjectAt < cfg.commitDelayMs) return 'too_soon'
  if (!ledger.modeDirty && ledger.expectedPos !== null && actualCursorPos() !== ledger.expectedPos)
                                    return 'cursor_mismatch'
  return null
}
```

判定失败时：**执行纯追加部分**（`tailNew` 中属于新增的内容），并把该段标记为 `committed`，上报 `segment.abandoned` + `reason`。

### 4.2 光标位置检查

macOS 取插入点最稳的方式是 Accessibility API：

```js
// 通过 osascript 的 System Events 取焦点元素（部分 App 不支持，取不到就跳过检查）
const script = `
tell application "System Events"
  set frontApp to first application process whose frontmost is true
  try
    set el to value of attribute "AXFocusedUIElement" of frontApp
    set r to value of attribute "AXSelectedTextRange" of el
    return item 1 of r
  on error
    return -1
  end try
end tell`
```

- 返回 `-1` 表示「拿不到」，此时**跳过检查**（不要因为拿不到就拒绝替换，否则很多 App 都没法用）
- 返回具体位置且与 `expectedPos` 不符 → 放弃替换
- `expectedPos` = 本会话注入的 Unicode 字符总数（每次注入后累加 `Array.from(text).length`）

> 注意：支持度因 App 而异，VSCode / Chrome 可用，部分原生 App 返回 -1。因此这一层是**增强保护**，真正的兜底是「插入模式」+「落定后不回改」。

## 5. 主循环与状态机

```
        ┌──────────┐
        │  idle    │◄──────────────── 断开/未配置
        └────┬─────┘
             │ connect
        ┌────▼─────┐  register 失败 → 关闭码 1008 → 提示检查配置
        │connecting│
        └────┬─────┘
             │ registered
        ┌────▼─────┐   收到 segment.snapshot → 判定 → 注入/替换 → ack
        │  online  │──────────────────────────────────────────────┐
        └────┬─────┘                                              │
             │ close/error                              ┌─────────▼────────┐
             └──────────────────────────────────────────►  reconnecting    │
                         指数退避 1/2/4/8…30s            └─────────┬────────┘
                                                                │
                                                   重连后收 recentSegments
                                                   → 只补发未见过的段（按 segId 去重）
```

**插入模式**：`insertMode` 为 `false` 时，收到快照只更新账本**不注入**（避免误注入），但会打印「[待插入] 你好我们…」。用户按全局热键切换后才真正注入；切换瞬间会把最近一条未注入的段落补上。

> v1 全局热键用最简方案：`voice-desktop` 运行在终端时监听 stdin 单键命令（`i` 切换插入模式、`s` 查看状态、`q` 退出）。真正的系统级全局热键（`⌥⌘V`）在 P1 用 `node-global-key-listener` 或 `skhd` 实现，避免 v1 引入原生依赖。

## 8. 权限与前置条件（macOS）

1. **辅助功能权限**：系统设置 → 隐私与安全性 → 辅助功能 → 勾选 `Terminal`（或运行 `voice-desktop` 的宿主程序）。没有它 `osascript` 的按键会被系统静默忽略。
2. **自动化权限**：首次运行 `osascript` 会弹「Terminal 想要控制 System Events」，必须允许。
3. 安全输入（密码框）：macOS 会直接屏蔽，注入失败 → 上报 `inject.error: secure_input`。

启动时自检并给出明确中文提示，不要静默失败。

| `你好我们` → `你好，我们明天` | tailOld=2, tailNew=`，我们明天` |
| `你好，我们明天见。` → 同文本 | 无操作 |
| `abc` → `abc` 但 rev 更小 | 忽略（幂等） |
| `表情😀好` → `表情😀好呀` | tailOld=0, tailNew=`呀`（emoji 不被拆） |

| `abandonAll` 后收到需要回改的快照 | 只追加，返回 `abandoned` |
