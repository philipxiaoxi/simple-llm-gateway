# 任务拆解与实施顺序

> 配套：[技术方案.md](./技术方案.md) · [协议参考.md](./协议参考.md) · [桌面客户端.md](./桌面客户端.md)
> 说明：每个任务都标注了**要动哪些文件**和**怎么验证**，可以逐条勾选推进。

---

## 阶段总览

| 阶段 | 目标 | 可验证结果 | 预估 |
|---|---|---|---|
| P0-1 | 数据与骨架 | 后台能创建房间并看到列表 | 0.5 天 |
| P0-2 | 裸链路（**先不做润色**） | 手机按住说话 → 电脑输入框实时出字 | 1 天 |
| P0-3 | 上屏与回执 | 电脑端回执、断线重连、插入模式 | 1 天 |
| P0-4 | AI 润色与替换 | 润色后原地替换 + 全套保护 | 1 天 |
| P0-5 | 日志与可观测 | 后台能看到完整事件链 | 0.5 天 |
| P1 | 体验完善 | 二维码 / 撤销 / 托盘 / 指标 | 1 天 |

> **强烈建议按 P0-2 → P0-3 → P0-4 的顺序做**。先确认「实时出字」的地基（手机浏览器采集 + 延迟 + WS 打通），再叠加润色和替换。替换算法是风险最高的部分，不要在链路未验证时就开始调它。

## P0-2 裸链路（先不做润色）

### T2.1 阿里云 ASR 客户端
- **文件**：`backend/app/services/voice_asr.py`（新）、`backend/requirements.txt`
- **内容**：`VoiceAsrSession.start/push_audio/finish/abort`；报文见 [协议参考.md §1.3](./协议参考.md)；事件解析 `result-generated → on_partial/on_final`；超时与 `task-failed` 处理
- **要点**：
  - `websockets.asyncio.client.connect(..., additional_headers={"Authorization": f"Bearer {key}"})`（17.x 用 `additional_headers`，不是 `extra_headers`）
  - 二进制帧直发 PCM，不做 base64
  - 显式 `pin websockets==17.0.1`（现在只是 `uvicorn[standard]` 的间接依赖）
- **默认模型**：`qwen-audio-3.0-asr-flash-streaming`（选型依据见 [技术方案.md §4.4.1](./技术方案.md)）
- **默认参数**：`disfluency_removal_enabled=true`（实测关掉时 ASR 一个赘词都不删）、`punctuation_prediction_enabled=true`、`max_sentence_silence=700`
- **验证**：`tests/test_voice_asr.py` 用假 WS 喂事件样本；真实链路自检直接跑已备好的 `scripts/voice_asr_probe.py`
  ```bash
  ALIYUN_DASHSCOPE_API_KEY=sk-ws-xxx ./.venv/bin/python scripts/voice_asr_probe.py
  # 传 --audio 16k单声道.wav 可验证真实转写效果
  ```

### T2.2 会话编排（不含润色）
- **文件**：`backend/app/services/voice_session.py`（新）
- **内容**：`handle_start/handle_binary/handle_stop/handle_discard`；`on_asr_final` 分段入库并广播；`session.done`
- **要点**：音频**直通转发**，不缓冲不转码；所有 DB 写入走 `await asyncio.to_thread(...)`；日志写失败必须吞异常（`*_safely` 模式）
- **验证**：手工 + `tests/test_voice_ws.py`（`client.websocket_connect`）

### T2.3 两个 WS 端点
- **文件**：`backend/app/routers/voice_rooms.py`
- **内容**：`/api/voice/rooms/{room_id}/phone`、`/api/voice/desktop/connect`；鉴权按 [协议参考.md §2.2](./协议参考.md)；失败关闭码 `1008`
- **要点**：**不要**用 `APIRouter(dependencies=[...])` 给 WS 挂依赖（仓库已验证会出问题）；在 handler 内 in-band 鉴权，照 `local_agent.py:77-104` 的写法
- **验证**：坏令牌 → 1008；正常 → `ready`

### T2.4 手机加入房间（公开接口）
- **文件**：`backend/app/routers/voice_rooms.py`、`backend/app/login_gate.py`（复用限流思路）
- **内容**：`GET /api/voice/rooms/lookup?code=`、`POST /api/voice/rooms/{id}/join`；返回房间作用域 JWT
- **验证**：房间码可查；PIN 错误 403 + 记 `room.pin_failed`；限流生效

### T2.5 手机端音频采集
- **文件**：`frontend/public/voice-worklet.js`（新，静态文件免打包）、`frontend/src/lib/voiceAudio.ts`（新）
- **内容**：`getUserMedia` → `AudioWorkletNode` → 累积 100ms → Float32→Int16 → 48k→16k 线性插值 → 回调输出 `ArrayBuffer`；`ScriptProcessorNode` 兜底
- **要点**：`AudioContext` 必须在用户手势里 `resume()`；`getUserMedia` 必须 HTTPS/localhost；`visibilitychange` 回前台提示重按
- **验证**：手机 Chrome 打开页面，控制台能打印每帧 3200 字节

### T2.6 手机端录音页（先只显示 ASR 原文）
- **文件**：`frontend/src/lib/voiceSocket.ts`（新）、`frontend/src/pages/VoiceJoin.tsx`（新）、`frontend/src/pages/VoiceSend.tsx`（新）、`frontend/src/App.tsx`
- **内容**：Pointer Events 按住说话 + 上滑取消 + 计时；WS 连接与重连；实时字幕区（未定稿浅色 / 定稿正常色）；状态条
- **要点**：`touch-action:none` + `setPointerCapture`；路由注册在 **Guard 之外**；公开页自己带 safe-area padding
- **验证**：iPhone Safari + Android Chrome 按住说话，屏幕上实时出字

### T2.7 打通到电脑端（临时最小实现）
- **文件**：`voice-desktop/`（新，先做 `index.js` + `ws.js` + 极简 `inject.js`）
- **内容**：注册、收 `segment.snapshot`、`pbcopy`+`Cmd+V` 注入、回 `segment.ack`
- **验证**：📱 说话 → 💻 微信输入框出字 ✅ **这是 P0 的里程碑**

## P0-4 AI 润色与替换

### T4.1 润色服务
- **文件**：`backend/app/services/voice_polish.py`（新）
- **内容**：`polish_text()` 复用 `bridge.call_chat` + `require_upstream_credential`；`clean()` 去掉 Markdown/引号/首尾空白；失败一律返回原文；可选写一条 `request_logs`（`protocol="voice_polish"`）
- **定位**：纠错层而非文风层。默认 `polish_mode=error_fix`（只修同音字/错别字/标点/赘余，不改写），提示词见 [技术方案.md §4.5](./技术方案.md)
- **必须实现**：`should_apply()` 过度改写保护（长度变化 >30% 或编辑距离 >40% → 放弃替换，保留原文并记 `applied=false`），见 [技术方案.md §4.4.3](./技术方案.md)
- **对标**：`backend/app/services/skills.py:370-421`
- **验证**：`tests/test_voice_polish.py`（成功 / 超时 / 异常 / 空返回，**必须回退原文**），`monkeypatch` `call_chat`（照 `tests/test_skills.py:177-188`）

### T4.2 接入会话编排
- **文件**：`backend/app/services/voice_session.py`
- **内容**：`on_asr_final` 后 `spawn(polish_and_revise(seg))`，不阻塞音频路径；竞态保护（后续段 ≥2 或终稿 >12s 则放弃应用）；全局润色并发信号量（默认 4）
- **验证**：连说 3 句，润色分别回来且各自替换正确

### T4.3 客户端替换落地
- **文件**：`voice-desktop/src/index.js`、`voice-desktop/src/segments.js`
- **内容**：三道闸（`replaceEnabled` / `insertMode` / `roomBusy` / `commitDelayMs` / 光标检查）；失败时只追加 + 上报 `segment.abandoned`
- **验证**：见 §9.2 手工验收清单

### T4.4 房间润色配置页
- **文件**：`frontend/src/pages/VoiceRoomDetail.tsx`（新）、`frontend/src/lib/api.ts`
- **内容**：账号 + 模型下拉（`GET /api/admin/voice/polish-accounts`）、**润色档位三选一**（`off` / `error_fix` / `rewrite`）、ASR 去赘词开关、提示词、温度、「用示例文本试润色」按钮（`POST /api/admin/voice/test-polish`）
- **要点**：「试润色」必须**同时展示 ASR 原文与模型输出**，让用户自己判断这一跳有没有价值
- **验证**：改完账号模型立即生效，不需要重启
